Multi-Agent Systems

Time: ~10 minutes. Tangible win: decide whether a task needs one agent, a workflow, or a lead agent with sub-agents, and state the reason in writing.

Multi-agent designs are appealing because they sound like a team. In practice, every added agent adds model calls, coordination, and new failure points. Anthropic's guidance is to start with the simplest design, measure it, and add agents only when measurement shows a gain.

Primary source Effective context engineering for AI agents, Anthropic: read the section on sub-agent architectures. It explains the main reason to split work across agents, which is context, not headcount.

The real reason to use sub-agents

A sub-agent is worth using when detailed exploration would crowd out the main task. The sub-agent works in its own clean context window, explores as much as it needs, and returns a condensed summary to the lead. Anthropic describes summaries of around 1,000 to 2,000 tokens returned from explorations that may use tens of thousands. The lead agent keeps the plan and synthesizes results, and never sees the raw exploration.

Parallel exploration is the second reason. Independent research threads can run at the same time, which is faster and keeps each thread focused. Specialization is a weaker third reason, because a single well-prompted agent often handles several roles.

The costs

Multi-agent systems use more total tokens than a single agent, because each sub-agent pays its own setup and returns its own summary. Coordination introduces failures where one agent misreads another's output. Debugging becomes harder, because a wrong answer may come from any branch. Each of these costs is real, and each must be justified by a measured gain on your eval.

Do not add agents to fix a prompt If one agent gets an answer wrong, first check the tool descriptions, the context it receives, and the eval. Splitting the work across more agents rarely fixes an unclear tool or a missing fact.

A decision test

Work through the options in order and stop at the first that meets the need. A single LLM call first. A workflow second. A single agent with good tools third. A lead agent with sub-agents last, and only when the exploration would flood the main context or parallel work is clearly valuable.

Practice

  1. Pick a research-style task from your work. Decide which of the four options above it needs, and write a paragraph defending that choice.
  2. If you chose sub-agents, define what each returns to the lead, and set a rough size limit on that summary.
  3. Name the eval from lesson 0006 that would prove the added agents are worth their cost. Write down the threshold you would accept.

Retrieval check

Correct. The sub-agent does the detailed work in its own window and returns a short summary, which keeps the lead's context focused.

Not quite. Sub-agents protect the lead's context by absorbing the detailed exploration and returning only a summary. They do not enlarge the window or remove tools.

Before adding agents to a system, what should you do first?

Correct. A simpler baseline shows whether added complexity buys anything. Without that measurement, you cannot know whether the extra agents help.

Not quite. Adding agents first and measuring later hides whether they helped. Measure the simpler design against your eval, then decide.
