Design Recommendation

Time: ~9 minutes. Tangible win: a defensible, written recommendation for the client's two pipelines — source mode, delivery guarantee, catalog — with every choice traceable to an earlier lesson. This is the deliverable.

Eight lessons of parts; now the assembly. The client has two inputs — job-history log files and MongoDB operational data — both landing in Iceberg for Dremio. This lesson makes the calls and justifies each, the way you would in a design review.

Primary source Your own earlier lessons — each recommendation below cites the lesson that establishes it. For the end-to-end reference pattern, Dremio's Flink SQL + Iceberg guide.

Pipeline A — Dremio job-history logs → Iceberg

Files landing continuously as engines run jobs, needed in Iceberg for analysis in Dremio.

The one flag to raise with the client The FileSystem source assumes write-once files (L4). If an engine rewrites a job-history file in place rather than rolling a new one, continuous mode won't re-read it. Confirm the logs are append-only/rolled before committing to this design — it's the question most likely to bite later.

Pipeline B — MongoDB operational data → Iceberg

Here the recommendation forks on a question only the client can answer: do they need a live view, or a periodic snapshot?

DecisionIf live view neededIf periodic snapshot
Connectormongodb-cdc (source-only)mongodb (bounded)
Stream kindUpsert changelogAppend
Iceberg tablev2, upsert enabled, PRIMARY KEY(_id)Plain append table
Infra costReplica set + always-on jobAny Mongo + scheduled run
LessonL2, L6L2, L6

Recommendation: default to the plain mongodb bounded read unless the client has a concrete need for sub-minute freshness. CDC is strictly more powerful and strictly more operationally expensive — a replica set, an always-running job, and the upsert-table complexity. Reach for it only when "live" is a real requirement, not a nice-to-have. This is the laziest-that-works call, and it's defensible precisely because it names what CDC costs.

Both pipelines share one catalog — that's the architecture Pipelines A and B write to different Iceberg tables but through the same catalog, and Dremio reads them through that same catalog (L7). That single shared catalog is the whole integration: Flink fills, the catalog governs, Dremio reads. If you remember one diagram from this course, make it that triangle.

What you can now do
