Devin's Five Modes

Lesson 1 · Leverage Devin on a New Project · ~7 minutes

Every Devin session runs in one mode, and the mode decides how much Devin does on its own before it stops to ask you. Pick the wrong one and you either babysit every edit or hand an unsupervised agent your whole machine. Learn the five modes and you control Devin precisely.

Your win

The Devin CLI has one mode selector with five choices: Ask, Plan, Code, Smart, and Bypass Permissions. Cycle them with Shift+Tab. Read-only first, more autonomy as you earn trust.

Docs lag the binary

Cognition’s published docs still describe an older model (separate “agent modes” and a permission mode called “Accept Edits,” plus an “Autonomous” mode). Your installed CLI is the source of truth. When in doubt, run /help or /mode to see the exact names your build accepts.

The five modes, least to most autonomous

ModeWhat it doesReach for it when
AskAnswers questions about the codebase. Makes no changes.Exploring an unfamiliar repo.
PlanScopes and plans a task into a prompt. Still no changes.Turning a vague idea into a plan.
CodeWrites code and auto-accepts edits in the workspace; prompts for shell commands.Executing a scoped task — the everyday default.
SmartLike Code, plus a fast model auto-runs other actions it judges clearly safe.Trusted, routine work you want to move faster.
Bypass PermissionsAuto-approves everything — writes and shell — with no isolation.Rarely, and only when you trust the whole run.
Read-only vs. write modes

Ask and Plan never change your code — they are the safe way to understand and scope. Code, Smart, and Bypass Permissions all write; they differ only in how much they ask before acting. Cognition’s advice holds: start in Ask to understand, move to Plan to scope, then to Code to execute.

Switching modes

Cycle modes with Shift+Tab, or set one directly with a slash command. Ask and Plan are one-shot-friendly for a single question or planning pass:

# Cycle: Shift+Tab steps through Ask → Plan → Code → Smart → Bypass Permissions

# Or set a mode explicitly:
/ask how does authentication work in this repo?   # read-only Q&A
/plan add rate limiting to the login endpoint     # scope it, no changes
/code                                             # switch to the write mode
/smart                                            # model-judged auto-approval
/bypass                                           # Bypass Permissions (confirm the name with /help)
Bypass Permissions has no safety net

Bypass Permissions auto-approves every tool call — file writes and shell commands — with no isolation. It never overrides organization rules an admin has set, but on your own machine it trusts the agent completely. On a first project, stay in Code so you see and approve what happens. Autonomy is trust you earn.

A typical first task

# 1. Explore in Ask (read-only)
devin
/ask where is the login flow handled?

# 2. Plan the change (still no edits)
/plan add a 5-attempts-per-minute rate limit to the login route

# 3. Execute in Code — edits auto-accepted, shell still prompts
/code
# ...review the diff; approve shell commands as they come
