# Mission

## Who

Ian Forster — Principal Consultant. Deep experience with AI agents (builds skills/agents,
runs agents at scale). Polyglot engineer. New to **Devin.ai** specifically — the CLI and
Desktop surfaces.

## What

Learn to **leverage Devin.ai (CLI + Desktop) effectively on a new project** — delegating
work to Devin as an autonomous coding agent, and orchestrating agent sessions well.

## Why

Ian is starting a new project and wants Devin to be a genuine force-multiplier from day one,
not a toy. The goal is a working mental model of *when* to use Devin, *how* to scope and
instruct it, *which* permission/agent mode fits each task, and how to review its output
safely — so he can ship faster and later advise on adoption.

## Definition of Success

Ian can, on a real repo:
1. Choose the right **agent mode** (Ask / Plan / Agent) and **permission mode**
   (Normal / Accept Edits / Smart / Bypass / Autonomous) for a given task, and explain why.
2. Scope a task to Devin using the "3-hour rule" with clear success criteria and context.
3. Onboard a repo for Devin (index, AGENTS.md, knowledge) so sessions start informed.
4. Run, steer, and review a Devin session end-to-end, including safe review of its diff.
5. Orchestrate multiple sessions / subagents for parallel work.

## Open Questions (to refine with Ian)

- The specific project stack (language, greenfield vs existing) — anchors examples.
- Leverage style: solo force-multiplier vs. fleet operator (both, likely — start solo).
- End goal: ship a feature vs. advise clients (both — bias toward hands-on shipping).

## Constraints / Preferences

- Concise, technical, no filler (see NOTES.md).
- Bias toward momentum: working draft first, iterate.
- Never teach from parametric memory — ground every claim in cited Devin docs.
