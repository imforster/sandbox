The six parts of a warehouse

Lesson 2 of 8. Time: 8 minutes. Tangible win: name the six warehouse components in order and say which are bundled.

The paper's argument depends on a component list, so memorize it. A traditional RDBMS-OLAP bundles all six into one unit (the paper's Figure 2). The lakehouse later pulls them apart.

The components

#ComponentJob
1Data storageHolds the bytes at a path in a file system.
2File formatDefines how data is written inside a file, by row or by column.
3Table formatA metadata layer over the files that makes them behave like a table.
4Storage engineKeeps files, indexes, and constraints up to date and handles create, read, update, delete.
5Compute engineRuns queries, transformations, and aggregations.
6CatalogA directory of datasets, using metadata such as table name and schema.

The paper notes that columnar formats perform better when reading large numbers of records, which is why analytics favors them (Section 2.1).

Memory hook

Bottom to top: bytes, file layout, table view, upkeep, queries, directory. The table format sits above the files and below the engines.

Retrieval check

Which component organizes a group of data files so they can be queried as a table?

Correct. The table format is the metadata layer that groups files into a logical table.

Not quite. The catalog lists tables and the engine runs queries. The table format is what makes files act like a table.

Practice

  1. From memory, write the six components in order.
  2. Draw them as a stack and mark where the files end and the metadata begins.
  3. Say in one sentence why bundling them creates lock-in (you will test this in Lesson 4).
Primary source The Data Lakehouse: Data Warehousing and More, Mazumdar, Hughes, Onofré (arXiv 2310.08697). Read Section 2.1 (Technical components). About 5 minutes.
