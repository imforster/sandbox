Glossary

Terms used in the data lakehouse lessons, defined as the source paper uses them.

A

ACID
Atomicity, consistency, isolation, durability: the four guarantees that make a transaction reliable.

C

Catalog
A service that tracks the tables in a system using metadata such as table name, schema, and a reference to the table format metadata.
Compute engine
The component that executes queries and transformations over stored data.
Copy-on-write (CoW)
An update strategy that rewrites affected files when records change: costlier writes, no extra read work.

D

Data as code
Managing tables with Git-like branches and commits, using tools such as Project Nessie and LakeFS.
Data lake
Low-cost storage that holds structured, semi-structured, and unstructured data in open files.
Data lakehouse
An architecture that brings data warehousing capabilities to a data lake using open file and table formats.
DW practices
Technology-independent data warehousing habits such as data modeling, ETL or ELT, and data quality.

E

ETL / ELT
Moving data between systems: extract, transform, load, or extract, load, transform.

F

File format
The layout of data inside a file, by row or by column, such as Apache Parquet.

M

Merge-on-read (MoR)
An update strategy that writes changes to extra files and reconciles them at query time: faster writes, slower reads.
Multi-version concurrency control (MVCC)
Transactions read a snapshot of committed table versions and commit by atomically updating the metadata that defines the table.
MPP
Massively parallel processing: spreading query work across a cluster of machines.

O

OLAP
Online analytical processing: large-scale analysis over many rows.
OLTP
Online transactional processing: live inserts, updates, and deletes touching one or a few rows.
Optimistic concurrency control
A way to allow concurrent writes by checking for conflicts at commit time instead of locking up front.

R

RDBMS-OLAP
In this course, the technology: a relational database built for analytics, commonly called a data warehouse.

S

Snapshot
A recorded state of a table at a point in time, kept by a table format and used for time travel and rollback.
Storage engine
The component that keeps files and structures such as indexes and constraints up to date.

T

Table format
A metadata layer over data files that makes them behave like a table, such as Apache Iceberg, Hudi, or Delta Lake.
Two-tier architecture
A data lake plus a warehouse, joined by ETL pipelines, which the paper says adds copies and complexity.

Z

Zone map
Per-file minimum and maximum column statistics used to skip files during query planning.
