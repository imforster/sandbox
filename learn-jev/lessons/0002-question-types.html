The Three Question Types

Time: 8 minutes. Tangible win: you can write a Jev call that asks a Noul, a Choice, and a Score about the same state, and read every answer back.

In Lesson 1 you learned to spot a Jev job. Now you learn the only three shapes a Jev question can take. Every decision you ever route to Jev is one of these three — memorize them and the API stops being a mystery.

Primary source TypeSafe Quickstart — docs.typesafe.ai (~5 min). The support-ticket example uses all three types in one call; this lesson walks through exactly that request and response.

Noul, Choice, Score

Noul

A yes/no statement. Returns the probability it's true, 0–1. "Is this urgent?" → 0.999.

Choice

Pick one from a fixed set. Returns a probability per option plus overall confidence. "Which team?" → billing.

Score

Rate against ordered levels. Returns a continuous score plus confidence. "How frustrated?" → 1.035.

Two rules that trip people up. First, Jev never invents options — a Choice picks only from the criteria you pass in. Second, a Score is continuous: with levels 0/1/2, a return of 1.035 means "just past 'frustrated but civil,' leaning toward angry." The decimal carries information a plain label throws away.

The call

The Python SDK reads TYPESAFE_API_KEY from the environment and defaults to jev-latest. One call, three questions, evaluated in parallel:

from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

client = TypeSafeClient()

ticket = ("Hi, I've been trying to connect my Stripe account for 3 days "
          "and it keeps failing. I'm losing sales. Please help ASAP.")

response = client.system_one(
    state=ticket,
    questions={
        "department": Choice(
            instructions="Which team should handle this",
            criteria={
                "billing": "Payment or subscription issues",
                "technical": "Bugs or integration problems",
                "sales": "Pricing or account questions",
            },
        ),
        "frustration": Score(
            instructions="How frustrated the customer appears",
            criteria=[
                "Calm, just stating facts",
                "Frustrated but civil",
                "Very angry, strong language",
            ],
        ),
        "is_urgent": Noul(
            instructions="The message conveys urgency or time-sensitivity",
        ),
    },
)

print(response.answers["department"].choice)   # "billing"
print(response.answers["frustration"].score)   # 1.035
print(response.answers["is_urgent"].noul)      # 0.999
The state is not a prompt

You pass state (the thing to evaluate) and questions (what to decide) as separate arguments. There is no prompt to engineer. The instructions field describes the decision, not how to think about it — Jev doesn't reason in text.

Reading the response

Each answer carries its type and its raw distribution, not just the top pick. A Choice returns per-option probabilities and a confidence; a Noul returns a single probability. This is the calibrated data you'll act on in Lesson 3:

"department": {
  "type": "choice",
  "choice": "billing",
  "probabilities": {"billing": 0.84, "technical": 0.159, "sales": 0.001},
  "confidence": 0.596
}

Retrieval check

You want Jev to rate how negative a review is, from mildly to extremely negative. Which single question type fits best?

Right. "Mildly to extremely" is an ordered scale, so a Score returns a continuous value that preserves how negative. A Choice would flatten that ordering into unrelated buckets.

The key word is "ordered." Noul is yes/no; Choice is unordered buckets. A ranked scale from mild to extreme is a Score, which keeps the ordering.
