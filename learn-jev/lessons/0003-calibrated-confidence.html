Reading Calibrated Confidence

Time: 7 minutes. Tangible win: you can turn Jev's probability and confidence into an act / review / escalate decision in code.

A label without a confidence is a liability. In Lesson 2 every answer came back with a probability and a confidence score. This lesson is about the single most important habit when building on Jev: branch on the confidence, not just the answer.

Primary source Confidence — TypeSafe docs (~5 min). Explains why RLCD produces calibrated probabilities and how to read them. Pair with the confidence-gated routing pattern.

Probability vs confidence

These are two different numbers and confusing them causes bad automation. The probability is how likely each answer is (billing 0.84). The confidence is how sure Jev is about that whole distribution (0.596). You can have a clear winner the model is only moderately sure about.

Calibrated is the word that matters. It means when Jev says 0.9, it is right about 90% of the time — the number tracks reality. TypeSafe's whole pitch is that a model which is right 95% of the time but never tells you which 5% it missed cannot safely automate anything. Calibration is what makes a threshold trustworthy.

First-party claim

Calibration quality is TypeSafe's own reported result under their RLCD training. It's the core promise, but there's no independent third-party audit yet. In production, verify calibration on your data before trusting a threshold blindly.

The act / review / escalate band

The standard pattern: pick two thresholds and split outcomes into three lanes.

≥ 0.90

Act. High confidence — let code proceed autonomously.

0.60–0.90

Review. Uncertain — hand to a human or a slower LLM.

< 0.60

Escalate. Low confidence — don't act on Jev alone.

ans = response.answers["department"]

if ans.confidence >= 0.90:
    route_to(ans.choice)            # act autonomously
elif ans.confidence >= 0.60:
    queue_for_human(ans.choice)     # suggest, let a person confirm
else:
    escalate_to_llm(ticket)         # too unsure — reason it out

The thresholds are yours to set from the cost of being wrong. Gating a destructive tool call? Push "act" to 0.99. Sorting low-stakes newsletter emails? 0.7 is plenty. The transcript's Bitcoin demo is the cautionary tale: high-stakes prediction is exactly where you widen the escalate band.

Retrieval check

Jev returns choice "refund" with probability 0.88 but confidence 0.44. Your act threshold is 0.90. What should your code do here?

Right. You gate on confidence, not the winning probability. A clear favorite the model is unsure about is exactly the case to escalate rather than auto-act.

Probability is which answer leads; confidence is how sure Jev is overall. You branch on confidence — 0.44 is well under 0.90, so escalate.
